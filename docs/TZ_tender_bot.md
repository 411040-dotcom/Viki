# Техническое задание: «Тендер-бот» и «Завод тендеров»

**Версия:** 1.0 (черновик)
**Дата:** 02.10.2026
**Исполнитель:** Kiwi-агент (Telegram)
**Заказчик:** владелец ивент-агентства

---

## 1. Назначение

Тендер-бот — Telegram-бот, который:

1. Каждые 4 часа собирает новые закупки по направлению **event** (организация мероприятий) с трёх площадок.
2. Показывает их пользователю карточками в Telegram.
3. По кнопке **«Запустить завод»** прогоняет выбранный тендер через цепочку ИИ-агентов («Завод тендеров»). На выходе получаются: разбор ТЗ, концепции, площадки, смета, мерч, контакты заказчика и презентация.
4. По кнопке **«Создать КП»** готовит коммерческое предложение для клиента.
5. Ведёт единую базу заказчиков и ЛПР для будущих рассылок.

## 2. Термины

| Термин | Значение |
|---|---|
| Тендер | Закупка с площадки: извещение и документация (ТЗ, проект договора, НМЦК) |
| ТЗ тендера | Техническое задание заказчика внутри документации закупки |
| НМЦК | Начальная (максимальная) цена контракта |
| Завод | Конвейер из ИИ-агентов, который обрабатывает один тендер |
| Этап | Один агент в заводе |
| ЛПР | Лицо, принимающее решения |
| КП | Коммерческое предложение |

## 3. Общая схема

```
[Планировщик, раз в 4 ч]
        │
        ▼
[Парсеры: B2B-Center │ Bidzaar │ zakupki.gov.ru]
        │
        ▼
[Нормализация → фильтр «event» → дедупликация → БД]
        │
        ▼
[Telegram: карточка тендера]──► «Неинтересно» / «В избранное» / «Запустить завод»
                                                                  │
        ┌─────────────────────────────────────────────────────────┘
        ▼
 Этап 1  Распаковщик ТЗ
 Этап 2  Концепт-агент
 Этап 3  Агент площадок
 Этап 4  Сметчик
 Этап 5  Мерч-агент
 Этап 6  Контакт-агент  ──► база заказчиков / ЛПР
 Этап 7  Генератор презентации
        │
        ▼
[«На доработку» │ «Завершить» │ «Создать КП»]
                                     │
                                     ▼
                     [Генератор КП → презентация КП]
```

## 4. Модуль сбора тендеров (парсинг)

### 4.1 Источники

| № | Площадка | Адрес | Способ получения |
|---|---|---|---|
| 1 | B2B-Center | b2b-center.ru | Поиск по ключевым словам или API, если доступен |
| 2 | Bidzaar | bidzaar.com | Поиск по ключевым словам или API, если доступен |
| 3 | ЕИС «Госзакупки» | zakupki.gov.ru | Расширенный поиск (44-ФЗ, 223-ФЗ), RSS или FTP-выгрузки ЕИС |

Каждый источник — отдельный модуль-парсер с общим интерфейсом `fetch(since) -> list[Tender]`. Новую площадку можно добавить, не меняя остальной код.

### 4.2 Расписание
- Запуск каждые **4 часа** (cron `0 */4 * * *`, часовой пояс Europe/Moscow).
- Ручной запуск командой `/scan`.
- В каждом запуске берутся тендеры, опубликованные или изменённые после предыдущего успешного запуска, плюс запас 1 час.

### 4.3 Фильтр «event»
Тендер считается релевантным, если выполняется хотя бы одно условие:
- **Ключевые слова** в названии или описании: «организация мероприятия», «проведение мероприятия», «корпоратив», «конференция», «форум», «тимбилдинг», «праздник», «новогодн», «выставка», «фестиваль», «церемония», «event», «ивент», «деловая программа», «культурная программа» и т. д. Список хранится в настройках и редактируется командой `/keywords`.
- **ОКПД2**: 82.30 («Услуги по организации конференций и торговых выставок»), 93.29 («Услуги в области отдыха и развлечений прочие»), 79.90 и другие из списка в настройках.
- **Стоп-слова** (исключение): «поставка», «ремонт», «канцтовары» и т. п., тоже из настроек.

Дополнительные настраиваемые фильтры: регион, НМЦК от/до, минимальный срок до окончания подачи заявок (по умолчанию не меньше 3 дней).

### 4.4 Нормализация и дедупликация
Все тендеры приводятся к единой модели (см. раздел 8). Ключ дедупликации — `source + external_id`. Если у известного тендера изменились поля (сроки, документация), карточка помечается «🔄 Изменения» и уходит пользователю повторно.

### 4.5 Скачивание документации
Для каждого релевантного тендера скачиваются файлы документации (PDF, DOC/DOCX, XLS/XLSX, ZIP/RAR). Из них извлекается текст, для сканов — через OCR, и сохраняется для этапа 1.

### 4.6 Карточка тендера в Telegram
```
🎯 [Площадка] Название закупки
🏢 Заказчик: …
💰 НМЦК: … ₽
📅 Подача до: …   |  Дата мероприятия: … (если указана)
📍 Регион: …
🔗 Ссылка на тендер

[🚀 Запустить завод] [⭐ В избранное] [🙈 Неинтересно]
```
- «Неинтересно» скрывает тендер. Причину можно указать, она нужна для будущей донастройки фильтра.
- Если за запуск ничего не найдено, бот ничего не пишет. Итог дня приходит одним сообщением в 19:00: «Найдено N, запущено M».

## 5. «Завод тендеров» — конвейер агентов

### 5.1 Общие правила
- Этапы идут **последовательно**. Каждый агент получает выход всех предыдущих этапов и исходный текст ТЗ.
- Результат каждого этапа сохраняется в БД (JSON и текстовое представление) и отправляется в Telegram отдельным сообщением с прогрессом: «Этап 2/7: Концепции ✅».
- После каждого этапа есть кнопки **[✏️ Поправить]** и **[🔁 Перегенерировать]**. «Поправить» принимает комментарий пользователя и перезапускает этап с ним, после чего пересчитываются все последующие этапы.
- Если этап падает, делается до 3 повторов. Если повторы не помогли, бот сообщает об ошибке, и завод встаёт на паузу с кнопкой «Повторить этап».
- Режимы: **авто** (все этапы подряд) и **пошаговый** (подтверждение после каждого этапа). Режим выбирается в настройках.
- Каждый агент отделяет **факты из ТЗ** от **предположений**. Предположения помечаются явно.

### 5.2 Этап 1. Распаковщик ТЗ
**Вход:** текст документации тендера.
**Выход:**
| Поле | Описание |
|---|---|
| Формат мероприятия | Конференция, корпоратив, выездное, гибрид, онлайн и т. д. |
| Тема / повод | |
| Дата(ы) и длительность | |
| Место / регион | Город, область, направление (например, «северо-запад Москвы») |
| Количество участников | |
| Заказчик | Название, ИНН, адрес |
| Бюджет | НМЦК, аванс, условия оплаты |
| Состав услуг | Список того, что обязательно по ТЗ (площадка, кейтеринг, техника, ведущий, трансфер, мерч…) |
| Требования к участнику | Опыт, лицензии, обеспечение заявки и контракта |
| Критерии оценки | Цена, качество, опыт и их веса |
| Сроки | Подача заявок, подведение итогов, исполнение |
| **Что уточнить** | Список вопросов к заказчику (неясности и противоречия в ТЗ). Можно сразу оформить как запрос разъяснений |
| Риски | Штрафы, жёсткие сроки, нереалистичный бюджет |
| Оценка «стоит ли участвовать» | Коротко: да / сомнительно / нет, с причиной |

### 5.3 Этап 2. Концепт-агент
**Выход:** **не меньше 3 концепций**. Для каждой:
- название и короткая идея (1–2 предложения);
- описание: сценарий, ключевые активности, атмосфера и стиль;
- соответствие ТЗ: какие требования закрывает;
- **почему мы выиграем**: преимущества перед типовыми предложениями;
- **рекомендации по подаче**: как лучше представить заказчику, на чём сделать акцент;
- примерный уровень затрат (эконом / средний / премиум) относительно НМЦК.

В конце — рекомендованная концепция с обоснованием. Пользователь выбирает концепцию кнопкой; по умолчанию берётся рекомендованная. Последующие этапы работают с выбранной концепцией.

### 5.4 Этап 3. Агент площадок
**Вход:** регион и направление из ТЗ, число участников, формат, выбранная концепция.
**Выход:** 3–7 площадок. Для каждой:
| Поле | Обязательно |
|---|---|
| Название | ✅ |
| Адрес | ✅ |
| Тип (лофт, загородный клуб, усадьба, замок, отель, конгресс-центр…) | ✅ |
| Вместимость (по рассадкам, если известно) | ✅ |
| Примерная стоимость аренды | ✅ |
| Почему подходит под концепцию и ТЗ | ✅ |
| Сайт / контакты площадки | желательно |
| Источник данных и дата проверки | ✅ |

Требования: площадки находятся через веб-поиск, а не придумываются. Если цена или вместимость не подтверждены, ставится пометка «требует проверки».

### 5.5 Этап 4. Сметчик
**Выход:** смета мероприятия в таблице (Telegram-сообщение и файл XLSX):
- статьи: площадка, кейтеринг, техника (звук, свет, экраны), декор, программа и артисты, ведущий, персонал, трансфер, мерч, полиграфия, фото/видео, страхование, непредвиденные расходы, агентское вознаграждение, налоги;
- для каждой статьи: количество, цена за единицу, сумма, комментарий;
- итог в сравнении с НМЦК: запас или перерасход в рублях и процентах;
- **комментарии сметчика**: что лучше добавить, где сэкономить, что взять в первую очередь, какую цену заявки рекомендует (с учётом конкуренции и снижения на торгах).

### 5.6 Этап 5. Мерч-агент
> ⚠️ Состав этапа нужно подтвердить (см. раздел 12).

**Выход:** 3–5 вариантов брендированной продукции под концепцию: позиция, тираж, примерная цена, сроки производства, почему подходит.

### 5.7 Этап 6. Контакт-агент
**Задача:** найти ЛПР и контакты заказчика и пополнить единую базу заказчиков.
**Источники:** контактное лицо из извещения или документации, официальный сайт заказчика, открытые реестры (ЕГРЮЛ: руководитель), прошлые закупки заказчика.
**Выход:**
| Поле | Описание |
|---|---|
| Организация | Название, ИНН, сайт, отрасль |
| Контактное лицо из закупки | ФИО, должность, телефон, e-mail |
| ЛПР | ФИО, должность (руководитель, директор по маркетингу или по персоналу и т. п.) |
| Источник каждого контакта | Ссылка |
| История | Сколько event-закупок было у заказчика, на какие суммы, кто выигрывал |

**Требования:**
- запись в таблицу `customers` / `contacts` с дедупликацией по ИНН;
- выгрузка базы командой `/customers` (XLSX/CSV) с фильтрами для рассылок;
- собираются только **общедоступные служебные** контакты. Источник фиксируется. Учитываются требования 152-ФЗ о персональных данных: правовое основание для рассылок и возможность удалить контакт по запросу.

### 5.8 Этап 7. Презентация по тендеру (внутренняя)
**Формат:** PPTX и PDF, отправляются файлом в Telegram.
**Структура:**
1. Титул: тендер, заказчик, НМЦК, сроки.
2. Что требуется: выжимка этапа 1, вопросы на уточнение, риски.
3. Концепции: все варианты, рекомендованная выделена.
4. Площадки.
5. Смета и рекомендованная цена заявки.
6. Мерч.
7. Заказчик и ЛПР.
8. Вывод: участвовать или нет, следующие шаги.

### 5.9 Финальные действия
После презентации бот показывает кнопки:
- **[🛠 Оставить на доработку]**: завод получает статус «на доработке». Бот спрашивает, какой этап поправить и что именно, и перезапускает его с последующими этапами.
- **[✅ Завершить]**: статус «завершён». Все материалы сохраняются в карточке тендера.
- **[💼 Создать КП]**: запуск генератора КП (раздел 6).

## 6. Генератор коммерческого предложения
**Вход:** все результаты завода и выбранная концепция.
**Выход:** клиентская презентация КП (PPTX и PDF) в фирменном стиле агентства:
1. Обложка с логотипами агентства и заказчика.
2. Понимание задачи.
3. Концепция мероприятия: идея, сценарий, визуальные референсы.
4. Площадка.
5. Программа и тайминг.
6. Мерч.
7. Стоимость (итог и укрупнённые блоки, **без внутренней маржи и комментариев сметчика**).
8. Почему мы: кейсы и преимущества агентства.
9. Контакты и следующий шаг.

Внутренние данные (риски, контакты ЛПР, маржа, оценка конкурентов) в КП **не попадают**.
Шаблон, логотип, цвета и кейсы агентства хранятся в настройках и загружаются один раз.

## 7. Telegram-интерфейс

| Команда / кнопка | Действие |
|---|---|
| `/start` | Приветствие и меню |
| `/scan` | Внеплановый сбор тендеров |
| `/tenders` | Список новых, избранных и тендеров в работе |
| `/factory` | Активные заводы и их статусы |
| `/customers` | База заказчиков и выгрузка |
| `/keywords` | Ключевые слова, стоп-слова, ОКПД2 |
| `/settings` | Регионы, НМЦК, режим завода, время дайджеста, шаблон КП |
| `/help` | Справка |

Доступ к боту только у пользователей из белого списка Telegram ID.

## 8. Модель данных (минимум)

- **tenders**: id, source, external_id, url, title, customer_name, customer_inn, region, nmck, currency, published_at, deadline_at, event_date, okpd2[], raw_text, docs[], status (`new` / `hidden` / `favorite` / `in_factory` / `done`), hash, created_at, updated_at.
- **factory_runs**: id, tender_id, status (`running` / `paused` / `needs_rework` / `done` / `error`), mode, selected_concept_id, started_at, finished_at.
- **stage_results**: id, run_id, stage (1–7, `kp`), version, input_json, output_json, output_text, files[], user_comment, model, tokens, cost, created_at.
- **customers**: id, inn (unique), name, website, industry, tenders_count, total_nmck.
- **contacts**: id, customer_id, full_name, position, phone, email, is_decision_maker, source_url, collected_at.
- **settings**: keywords, stop_words, okpd2, regions, nmck_min/max, factory_mode, digest_time, brand_template.

## 9. Нефункциональные требования
- **Надёжность:** если одна площадка недоступна, остальные продолжают работать. Ошибки логируются, после 3 подряд неудачных запусков приходит уведомление.
- **Анти-бан:** паузы между запросами, ротация User-Agent, соблюдение ограничений площадок.
- **Скорость:** полный проход завода не дольше 15 минут. Карточки тендеров приходят не позже 10 минут после старта сбора.
- **Версионность:** каждая перегенерация этапа сохраняется как новая версия, к старой можно вернуться.
- **Стоимость:** токены и стоимость ИИ считаются по каждому этапу и заводу, есть сводка за месяц.
- **Секреты** (токен бота, ключи API, учётные данные площадок) хранятся в переменных окружения, а не в коде.
- **Бэкап БД:** ежедневно.

## 10. Критерии приёмки
1. Сбор срабатывает каждые 4 часа. За неделю нет пропусков и дублей карточек.
2. На тестовой выборке из 30 закупок фильтр «event» даёт не меньше 90% точности (доля нерелевантных не больше 10%).
3. Завод проходит все 7 этапов на 5 реальных тендерах без ручного вмешательства.
4. Каждый этап выдаёт все обязательные поля из раздела 5. Концепций не меньше трёх. У каждой площадки есть адрес, вместимость, тип, цена и обоснование.
5. Смета сходится арифметически и сравнивается с НМЦК.
6. Контакты попадают в базу без дублей по ИНН, выгрузка `/customers` работает.
7. Внутренняя презентация и КП открываются в PowerPoint и PDF. В КП нет внутренних данных.
8. Кнопки «Поправить», «На доработку», «Завершить», «Создать КП» работают как описано.

## 11. Этапы разработки
1. **MVP-1:** парсинг трёх площадок, фильтр, карточки, БД. Сейчас уже работает: проверить по разделу 4.
2. **MVP-2:** завод, этапы 1–4. Работает: привести выходы к обязательным полям.
3. **MVP-3:** этапы 5–7, база заказчиков, внутренняя презентация.
4. **MVP-4:** генератор КП в фирменном стиле, правки по этапам, версионность, статистика.
